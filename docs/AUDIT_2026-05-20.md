## Bugs/Risks Found And Fixed

- Fixed local API CSRF risk: state-changing requests now require local Host/Origin and cross-site POSTs return `403`.
- Fixed web-auth CDP profile confusion: if a CDP port is already running, Hallow now requires an active provider ownership lock or explicit `--attach-existing`.
- Fixed web-auth ownership continuity: active lock preserves the launched browser PID so repeated `open` can verify the port still belongs to that provider.
- Tightened web-auth readiness: policy must keep manual login, origin allowlist, audit artifacts, no cookie export, no token extraction, and no password capture.
- Added `gateway.csrf_guard` into `hallow security audit`.
- Added OpenClaw-style shared-secret local API auth: state-changing requests require `X-Hallow-Token` or `Authorization: Bearer`.
- Added `hallow security api-token status|rotate`; CLI redacts the token and prints only a short digest.
- Added Aeon-style usage ledger: `hallow agent run` now records provider/model, token estimate, duration, trace id, and cost estimate from a static provider price profile.
- Added `hallow usage report|list` for local runtime cost/token audit.
- Added Hermes-style external skill sources: `hallow skill source add`, `hallow skill hub`, and `hallow skill install-hub`.
- Added Aeon-style repeated repair loop: `hallow autonomy heal` runs rounds until quality is healthy or max rounds is reached.
- Added rolling 30-run degradation policy for skill quality snapshots.
- Added OpenClaw-style gateway pairings: `hallow gateway pair`, hashed pairing registry, `--pairing-token` ingestion, and allowlist activation.
- Upgraded marketplace signing from digest-only metadata to Ed25519 keypair signing and verification.
- Added generic OpenHuman-style auto-fetch: `hallow integration autofetch run|add` fetches watched web sources into local memory or schedules repeat fetches.

## Remaining Product Gaps

- Web-auth is safe profile login, not a full ChatGPT/Claude web adapter yet.
- Hallow intentionally does not inspect cookies/tokens, so it cannot automatically prove a provider is logged in.
- OAuth token vault is local and redacted in CLI, but not encrypted/keychain-backed yet.
- No native packaged desktop installer yet.
- No OpenClaw-grade WhatsApp/Telegram/Discord/iMessage/Teams live gateway parity with real provider credentials.
